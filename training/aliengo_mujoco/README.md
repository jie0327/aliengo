# AlienGo MuJoCo 强化学习实验

这里提供独立的模型和训练入口。PPO、A2C、SAC 已各运行过一次 4096 步的小规模实验；独立评估中三种策略都略向后漂，**尚未学会前进**。模型和策略仍需要进一步验证，不可直接用于真机。

## 模型与任务

原型读取宇树 `unitree_ros` 展开的 AlienGo URDF，删除视觉网格，使用 MuJoCo 的 URDF 导入器生成浮动机身、地面及 12 个受限力矩执行器。转换时显式保留合并后机身惯量，并检查关节、执行器和总质量。摩擦参数、关节 PD 和奖励函数是实验假设，并非真机参数标定；地面、接触、电机与控制接口尚未验证。

动作是 12 个关节目标偏置，位置 PD 生成力矩；观测含机身速度、角速度、投影重力、关节状态、上一步动作和目标前速。训练代码可选择 Stable-Baselines3 的三种算法：

| 算法 | 入门时可以关注什么 |
|---|---|
| PPO | 收集一批经验后更新策略，先观察训练前后的变化。 |
| A2C | 用价值估计帮助更新策略，流程相对直接。 |
| SAC | 从经验回放中重复取样更新，适合连续动作；计算量可能不同。 |

三者使用同一机器人模型、任务、单环境、训练种子 19 和相同的环境交互步数；训练前后均在独立种子 1001、1002、1003 上用确定性动作评估回报、前向位移、高度和最大倾角。算法每次更新的方式和次数不同，交互步数相同不代表计算时间相同；记录的耗时可供对比。这只是统一的初步对比，三次评估和短训练不能证明算法排名或策略已经学会走路。

## 隔离和资源约束

训练镜像 `aliengo-learning:ppo-cpu` 在项目的 `aliengo-learning:noetic` 上添加 Python 3.8 兼容版本：MuJoCo 3.2.3、Gymnasium 0.29.1、Stable-Baselines3 2.3.2、NumPy 1.24.4、pandas 2.0.3。运行时只读挂载已有 `.ros1_rl/site` 的 PyTorch 2.4.1+cpu，避免再次下载 CUDA 版本或复制本机 PyTorch。这套组合已完成 4096 步实验；上游依赖的间接版本及 Ubuntu 软件包未全部固定，软件源变化可能影响重建。

训练入口关闭 GPU、设置 OMP/OpenBLAS/MKL 等线程数为 1、使用 1 个环境且不创建并行采样进程；PyTorch 也设置为单线程。Docker 训练容器限制为 4 GiB 内存、无额外 swap、2 核与 64 个 PID；训练进程额外设置 Linux `RLIMIT_AS` 4 GiB，只可向下调整。这是虚拟地址空间上限，不是系统级内存预留；PyTorch 映射的虚拟地址可能超出 4 GiB，从而拒绝启动，失败时应记录并停止。每回合最多 500 步；总训练量可指定为 256 的正整数倍，以确保三种算法执行相同的交互步数。镜像构建上限为 3 GiB 和 2 核；URDF 准备容器上限为 1 GiB 和 1 核。

`ros1_sim.sh`、ROS1 构建入口和本目录的容器入口使用同一个非阻塞 `flock`；运行前也检查 `aliengo-ros1-sim` 和 `aliengo-ppo-train` 是否已运行。锁随启动脚本退出而释放，已运行容器不会被停止或删除。这保护通过这些脚本启动的进程；直接使用 `docker run` 或直接调用 Python 会绕开锁。请勿并行运行这些任务。此前启动且不持有锁的仿真容器仍可由容器状态检查识别。

现有 `.ros1_rl/site` 约 751 MiB，缓存的 CPU torch wheel 约 186 MiB。主程序的 Linux Python 3.8 wheel 公开大小：MuJoCo 3.2.3 约 5.8 MiB、NumPy 1.24.4 约 16.5 MiB、Gymnasium 0.29.1 约 0.9 MiB、SB3 2.3.2 约 0.2 MiB；pandas 和其他间接依赖、安装后的展开以及 Docker 层会额外占用空间，完整镜像大小尚未测量。PPO 层复用已有 Noetic 基础镜像层，但重建仍需软件源可用。

| A2C | -0.029、-0.033、-0.033 | [结果](../../.ppo-work/verified-a2c/result.json) |

这证明训练和评估流程运行过，不说明已经学会沿目标方向行走。

同样条件下，三种算法也各运行了 100096 步。每条评估最多 500 步（10 秒仿真时间），三个种子只改变初始关节位置：

| 算法 | 三次位移（米） | 评估结果 | 报告 |
|---|---|---|---|
| PPO | 0.461、0.471、0.465 | 均在约 0.84–0.88 秒因姿态终止 | [结果](../../.ppo-work/extended-ppo/result.json) |

这些结果说明三个算法的训练与评估链路可运行，**尚未得到稳定前进的策略**。训练速度目标固定为 0.2 m/s，不是键盘速度跟踪；这三次评估不覆盖其他地形或负载。保存的策略只供这个 MuJoCo 实验使用，尚未接入 Gazebo 关节控制。

## 如何运行

首次准备环境时，先确认 ROS1 仿真已关闭、`.ros1` 工作区和 `.ros1_rl/site` 已准备，再按顺序执行，不并行：

```bash
cd /home/jack/aliengo_learning
python3 scripts/ros1_rl_setup.py
./scripts/ppo_build_env.sh
./scripts/ppo_prepare_urdf.sh
```

第二步只展开已有官方模型，不启动 Gazebo；文件 `.ppo-work/aliengo.urdf` 已存在时拒绝覆盖，可以直接使用现有文件。约 10 万步的示例采用最接近且不小于 10 万的 256 的倍数 100096：

```bash
./scripts/rl_train.sh ppo ppo-long 100096
./scripts/rl_train.sh a2c a2c-long 100096
./scripts/rl_train.sh sac sac-long 100096
```

三个命令依次运行，每次训练完成后再启动下一次；运行目录已存在时拒绝覆盖。输出包括转换模型、策略和 `result.json`，其中记录算法名称、参数和实际环境步数。原来的 `./scripts/ppo_train.sh ppo-run 4096` 仍是 PPO 的兼容入口。长训后需要查看独立评估的位移和倾角，再判断是否学会前进；GPU/CUDA 训练尚未配置。
