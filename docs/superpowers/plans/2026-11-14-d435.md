# AlienGo D435 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add usable RGB, metric depth and point-cloud streams to the current AlienGo Gazebo simulation.

**Architecture:** Add an independent RGB-D xacro to the existing project overlay, using pinned PAL RealSense source and a local RGB projection correction. Pass optional camera controls through the existing launcher and arrange X rendering even without the Gazebo GUI.

**Tech Stack:** ROS Noetic, Gazebo Classic 11, xacro, Bash, Python rospy.

**Spec:** `docs/superpowers/specs/2026-11-14-d435-design.md`

## Global Constraints

- Preserve upstream reference models and current MID360 topics.
- Default RGB `1280×720`, depth `848×480`, `30 Hz`, separate optical frames, configurable pose.
- Default camera enabled, optional `d435_enabled:=false`.
- No hardware driver or new geometry; build the pinned community simulation plugin.
- Workspace has no Git repository; work in place, do not initialize Git or create commits/worktrees.

## Review Focus

- Depth sensor sees the scene instead of its housing or the robot's trunk.
- Point clouds and CameraInfo agree with the optical TF.
- `--headless` can render camera frames; missing Xvfb gives a useful error.
- Disabled camera preserves existing non-rendering usage.
- Super-LIO launcher still forwards the camera settings correctly.

**Interfaces:** Produce separate color/depth/infrared frames and images, their CameraInfo and /camera/depth/color/points; expose mount, sizes, rate, FOV, range and nominal baselines.
