# GBPlanner 实机部署准备

目标：为 2026-11-16 的 AlienGo + MID-360 + D435 接入准备本机 Docker 运行环境、原厂高层 SDK 桥接、独立实机入口和简短部署说明。

采用现有 Docker/Noetic 工作区，复用已修补的 GBPlanner、融合和跟随器。相较重新安装宿主机 ROS 或启动缓存镜像中的旧工程，这个方式保留当前验证过的源码和参数。工作在现有目录；Git 尚无首个提交且全部文件未跟踪，不迁移或提交用户现有内容。

- 实机使用系统时间，不依赖 `/clock`；仿真保留原有时钟检查。
- MID-360 使用官方 CustomMsg 真逐点时间；IMU g 转 m/s²并标为真实 IMU 芯片坐标系。LIO 使用官方 MID360 分支，导航采用完整去畸变回波；补回被注册盲区排除的 .2–1m 近场，依照采样时间与 LIO TF 去畸变，不改注册过滤参数。
- 用户确认 D435 留在机上，通过网线接笔记本。机上只发送深度/RGB图与内参、内部TF，笔记本用官方 depth_image_proc 生成 XYZ，避免密集点云重复传输。提供相机环境探测、暂存源码、启动、显式系统时钟同步脚本；不自动结束原厂视觉进程或安装机载系统依赖。
- 外参必须按实物填写，模板不冒充标定；相机内部 TF 由官方驱动发布。
- SDK 桥接仅发送 HighCmd，适配当前协调器话题/服务。保留原命令时效和速度上限，站立确认来自新鲜 HighState；遥控退出与反馈/命令中断使速度归零。不开低层电机控制。
- 用户指出现有 `unitree_legged_sdk_v3.8.4`；已确认提交 `1c6226d3a6608432b43d1e488c5816ba134a354e`，直接使用其头文件和动态库。之前的接入记录确认运动程序 1.0.20、地址 .123.220；SDK要求 H0.1.7/H0.1.9 固件至少0.1.35，电机固件仍需现场确认。
- 不改官方空间政策、原尺寸/余量/跟随门限，不增加地图校验层。
- 今天验证编译、无硬件 ROS/UDP 回环和部署命令；实际设备网络、外参、驱动数据及运动仍须现场验证。
