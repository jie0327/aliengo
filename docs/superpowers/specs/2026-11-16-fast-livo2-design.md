# FAST-LIVO2 接入设计

用户要求在 AlienGo 项目中尝试接入 FAST-LIVO，并已明确选择 FAST-LIVO2。
用户补充要求：FAST-LIVO2 提供单独启动命令，不能破坏现有仿真。现有仿真、传感器模型、Super-LIO 和 GBPlanner 默认入口保持行为不变；新增共享脚本分支仅由 FAST-LIVO2 独立入口显式启用。

## 方案

新增独立 `.fast_livo` 工作区和 Docker 镜像，复用现有 ROS1 仿真、MID-360 与 D435。相比替换 Super-LIO，此方案便于分别运行和对照；不在同一 ROS 图中同时发布两套定位 TF。暂不将新估计器接入 GBPlanner 或真实电机控制。

固定官方源码和依赖提交，参考源码保留原样，本地补丁只应用到工作副本。当前仓库无初始提交且全部文件未跟踪，直接增量修改并为已有文件留备份，不创建空 worktree 或提交整个现有项目。

## 数据与接口

- 输入 `/livox/lidar` XYZ 瞬时点云、`/livox/imu` SI 单位惯性数据、`/camera/color/image_raw` RGB 图像。
- 只依据静态 URDF 安装关系与相机 CameraInfo 设定内外参；Gazebo 真值只用于误差评估。
- 仿真点云所有点具有同一真实采样时刻，不伪造逐点扫描时间；适配 FAST-LIVO2 同步与去畸变路径。
- 估计坐标系 `livo_map`，发布 `/fast_livo/odom`、配准点云、轨迹和估计的 `livo_map -> base` TF。
- 独立启动命令沿用先仿真、站稳、后启动估计器的顺序。输出地图放在每次运行的独立目录。
- 相机配置与实际图像尺寸/外参必须一致；优先从运行时 CameraInfo 和静态 TF 生成，避免用户改仿真参数后静默失配。

## 验证

实际 Docker 编译；有界仓库仿真；检查三个输入、非空地图/轨迹、有限位姿、带原时间戳的 TF、实际视觉更新证据与退出保存。能录制时进行传感器独立回放，报告精度和失败，不将启动成功称为融合有效。文档记录仿真与实机标定、同步的边界。
