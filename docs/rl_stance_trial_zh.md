# 策略接管前站姿过渡：隔离试验方案

该试验只在独立、无网络的仿真容器中执行，不使用真机，也不作为用户日常控制入口。两组各做过一次：基线进入策略后机身高度跌至 0.247 m；过渡组在进入策略前已跌至 0.231 m，两组均因阈值停止。初始站姿与策略训练默认姿态不同，但这些结果不能确定失稳原因。

对同一个试验脚本分别运行 `--baseline` 和 `--calibrate`：两组都启动 Gazebo、Guide 站立、关闭 Guide、核实电机命令话题没有其他发布者，然后使用同一策略和零速度意图；仅后者先按每步最多 0.05 rad 缓慢过渡到策略默认关节目标。固定模型、PD 增益、观测、时钟和其他条件。每组单独启动并结束仿真，比较接管后的高度、姿态、关节与动作。单次成败都不能证明一般稳定性，需要重复并记录完整条件。

由统一调度在确认没有其他容器运行后执行：

```bash
./scripts/verification/ros1_rl_closed_loop_trial.sh --baseline
./scripts/verification/ros1_rl_closed_loop_trial.sh --calibrate
```

脚本拒绝在已有 Docker 容器运行时启动；每次只启动一个 `--network none`、4 GB 内存、4 CPU 的容器，外层限时 300 秒。仿真反馈缺失/过期、时钟停止、推理周期超过 0.06 秒、数据非有限、横滚或俯仰超过 0.35 rad、机身高度低于 0.25 m 时，试验停止并关闭仿真。每次输出目录独立，包含 Gazebo 与 Guide 日志、`summary.json`，后者逐帧保存时间、姿态、关节位置、策略动作和目标。试验不包含行走或真机验收；仿真执行器为 PD，原训练使用 actuator network，模型质量等也不同。

两次实测分别在 `logs/rl-closed-loop-C6zCCL/summary.json` 与 `logs/rl-closed-loop-w3w7Gn/summary.json`。基线只运行策略约 0.255 秒，过渡组未进入策略阶段，因此不能据此评价策略走路能力。接管时支撑力矩下降是待验证的假设。
