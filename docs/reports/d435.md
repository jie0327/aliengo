# D435 接入与验收（2026-11-14）

在当前 Docker ROS Noetic / Gazebo 11 环境中，保留 AlienGo 现有外观，添加独立 RGB、深度和左右红外传感器。未增加相机外壳、碰撞或质量。使用固定 PAL RealSense 社区插件与独立本地补丁，不使用真机驱动。

命令：

```bash
./scripts/ros1_build.sh
./scripts/verification/d435_trial.sh
```

完整通过记录：[result.json](../../logs/d435-trial-IBIo7f/result.json)、[逐像素投影数据](../../logs/d435-trial-IBIo7f/color_projection_row.json)、[Gazebo 日志](../../logs/d435-trial-IBIo7f/roslaunch.log)。

## 构建、兼容与回归

- `./scripts/ros1_build.sh` 编译通过，最终优化构建日志为 [build-optimized.log](../../logs/d435-integration/build-optimized.log)。
- 单元测试 `python3 -m unittest discover -s tests -v`：159 项，152 通过、7 跳过。
- 实际 C++ 投影/编码/毫米换算测试先失败后通过；覆盖视场、尺寸、基线正负、旋转、越界、非有限深度和溢出。
- 默认、自定义六自由度安装/分辨率、关闭相机均经过 xacro 与 Gazebo SDF 展开检查；固定关节合并后传感器位置保持正确，物理几何数量不变。
- 最终优化构建另外实际通过自定义参数验收：RGB640×360、深度424×240，安装 X=0.34 m、Z=-0.04 m、偏航0.1 rad；几何和颜色投影均通过，记录为 [自定义参数 result.json](../../logs/d435-trial-kk1Lx9/result.json)。
- 主入口 `--headless d435_enabled:=false` 在无 DISPLAY 时可启动：实际收到 849 点的 MID360 帧，没有 `/camera/` 发布话题。
- 主入口无 DISPLAY 且旧镜像没有 Xvfb 时会明确提示依赖，而非静默产生空图像；虚拟显示实际运行未在这次旧镜像上验证。新基础镜像 Dockerfile 已声明 xvfb/xauth。
- 原有无显示的键盘和 Super-LIO 专用回归显式关闭相机，避免引入图形依赖；有图形环境的回归仍可加载相机。
- 新插件加入编辑器编译数据库，导出 106 条命令。
- 独立代码审查未发现阻塞问题；静态验收没有覆盖模型反复加载卸载、运动同步和长期频率稳定性。

裸 `pytest -q` 会进入项目附带的 `.ros1_rl/site/sympy`，因环境缺少 `hypothesis` 在收集阶段失败；项目范围 `pytest -q tests` 通过。这属于附带 Python 环境的测试收集问题，不是相机测试失败。

## 已修正的问题与边界

验收实际发现并修正了：社区插件共享 RGB/IR 图像缓存、不同视场/尺寸按同一像素取色、颜色通道顺序、点云与 CameraInfo 主点不一致、CameraInfo 旋转矩阵为空、非有限深度转换，以及 Gazebo R8G8B8/L8 名称导致的启动异常。原始源码保持固定版本，本地修改可单独审阅。

安装位置、视场和相机间外参仍为公开名义值或模型估计。深度由场景几何直接生成，尚未模拟主动双目匹配、真实噪声、孔洞、曝光、运动模糊、透明/反光失效。RGB 使用最近缓存帧并保留其位姿，不保证 RGB 与深度严格同步，也未解决两视角间动态遮挡。详细使用方法见 [D435 说明](../d435_sim_zh.md)。
